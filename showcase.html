Contract Lifecycle Ontology

AI reads signed contracts and operates the lifecycle for NDA, MSA, SOW, and Order Form. The ontology decides what the model extracts, what it is allowed to change, and which of its actions go through. Every attempt is audited.

Why AI needs the ontology here

Without an ontologyWith this ontology
"Extract the key terms" returns free text and invented fieldsThe extraction prompt is generated from the schema, and a guard keeps only known properties with valid types
Validation compares strings, so 2029-02-01 and February 01, 2029 look differentValues are typed, so dates and money compare by meaning
An agent with write access can edit any record, sign for a partner, or delete the evidenceThe agent's tools are the ontology's actions; state, link, lock, and delegation rules decide what happens
No record of what the AI triedEvery attempt, allowed or blocked, is in the audit log with the actor

The model

Contract is the hub. The governed_by link from a SOW or Order Form to its MSA lets a rule read the contract hierarchy.

start_review · Legal and BD→execute · Partner→submit · BD→lock_and_bill · Billing→validate · AI

Three places the ontology meets AI

1 · Extract

The schema is the prompt, the types are the guard

The model is asked to fill the Contract schema, not to "find the key terms." Its answer is checked against property types before it reaches any record.

def schema():
    types = OBJECTS["Contract"]
    return {p: types[p] for p in DOC_BINDING.values()}

# guard on a malformed model answer
rejected end_date='sometime in late 2027': not a valid date value
rejected total_value='about 98k': not a valid money value
ignored 'auto_renew': not a Contract property
rejected billing_lines.M3='TBD': not a valid money value
2 · Validate

Typed comparison against the locked record

The guarded extraction is compared with the Contract and its BillingLines. Findings are typed fields, so the eval can score them against ground truth.

CT-2 payment_terms  system Net 30      | signed Net 45
CT-3 billing_lines  system M2=51000.0  | signed M2=63000.0
CT-3 total_value    system 86000.0     | signed 98000.0
CT-6 end_date       system 2027-04-01  | signed 2027-10-01
3 · Act

Agent tools are generated from action types

The agent gets one tool per action plus read and edit. Delegation keeps signing with the Partner; locks, link rules, and the property list apply to the agent like anyone else.

tools = [{"name": a,
          "description": f"Owner: {owner}. Allowed from: {allowed}."}
         for a, (owner, allowed, _) in ACTIONS.items()]

DELEGATED_TO_AGENT = {"submit", "lock_and_bill", "validate"}

Agent run: "get every contract to Finance and resolve issues"

CT-2 is still in review with Legal. Everything else is signed. The agent works only through the generated tools.
